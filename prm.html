平台规则与协议管理中心（PRM）

面向法务的统一协议与规则管理工具：把平台对外规范性法律文件（隐私政策、服务协议等）做集中台账、标准化起草—审核—发布流程，并支持各业务线自定义扩展范围。一期先打通"可线上化、可复用"的最小闭环，再逐步放大。

发起　数据合规 / 产品合规法务
参与方　各业务线法务 BP、其他职能与业务团队
执行方　技术研发中心
版本　v1.0 一期范围
日期　2026-09-04

1一期目标：解决三件最痛的事

不追求"大而全"，先把最核心的"台账集中 + 流程标准化 + 范围可扩展"跑通。

资产散、版本乱

协议散在网盘/代码库/邮件，哪版生效说不清；跨业务线口径不一致。

更新发布无流程

谁改的、谁批的、何时发布无留痕，监管问"依据哪版"答不上。

覆盖受限、难扩展

现有仅支持个别平台/协议类型，其他业务线协议接不进来，复用无从谈起。

一句话：PRM 是平台协议与规则的统一真源——资产集中记账、流程标准留痕、范围可按业务线扩展接入。

2一期范围：3 个核心交付

① 协议 / 规则范围自定义扩展可扩展

产品一期做成可扩展的架构，支持把其他平台的协议 / 规则逐步扩展接入，不锁死平台与协议类型。现状：目前仅支持朴朴超市、森山的《隐私政策》《服务协议》更新与发布，覆盖有限——一期重点就是把"范围可扩展"做成产品能力。

② 平台协议资产台账集中

统一台账管理，支持分类（隐私政策/服务协议…）、状态（草稿/评审/生效/废止）、版本查看与检索，做到资产"一本账"，告别散落。

③ 起草 / 修订 / 更新 / 审核 / 发布 流程标准化

在线起草与版本留痕；标准审核 / 会签流程，全程留痕（具体审批方式待定，不自研工作流）；发布记录公示 / 生效状态。硬约束：不走完审核不许置"生效"（状态机不可绕过）。

3标准流程：一期生命周期

协议与规则资产走同一条标准化生命周期，修订 / 废止触发重评审并回流台账。

硬约束：未走完审核的资产，系统拒绝置为"生效"（状态机硬约束）。

4致各业务线法务 BP：一起把它用起来、完善起来

本系统定位为平台协议与规则的统一真源，欢迎各业务线法务把可线上化的协议 / 规则纳入管理。请协助以下三件事：

  • 历史收集：帮忙梳理本业务线已发布的协议 / 规则历史版本（含已废止的），统一导入台账，先把"一本账"补全。
  • 扩展接入：后续如有各自业务条线可线上化管理的协议、规则，直接通过本系统维护——一期已做成可扩展架构，支持把其他平台协议扩展进来。
  • 需求共建：使用中提出的产品需求、优化点、字段 / 流程建议，随时提，一起迭代完善 PRM。
协同机制：数据合规 / 产品合规法务负责底层能力与范围扩展框架，各业务线法务 BP 及其他职能、业务团队参与本领域资产归集与需求反馈；执行方为技术研发中心，负责系统建设与交付。以现有已支持的朴朴超市、森山为起步样本，验证范围可扩展框架后，按业务线复制推广其他平台协议。
本版为一期范围同步与协同征集稿，聚焦"范围可扩展 + 台账集中 + 流程标准化"
长期能力（深度执行打通 / 隐私政策自检 / C 端规则中心对接）已纳入演进路线，不在本期
